第一章：橘子岛是什么

橘子岛是一款 BYOK（Bring Your Own Key）Android AI 客户端，它本身不提供 AI 聊天服务，而是作为统一入口，让你连接多个 AI 提供商。

使用橘子岛前，你必须自行准备至少一个 AI 服务提供商的 API Key。橘子岛不售卖、不提供、不赠送 API Key 或模型调用额度。

橘子岛支持以下 8 个内置提供商：

编号提供商说明
AOpenAIGPT 系列、o1/o3 推理模型
BAnthropicClaude 系列
CGoogle GeminiGemini 系列，支持代码执行与搜索插件
DDeepSeekDeepSeek-V3 / R1 等
EQwen（DashScope）阿里通义千问系列
FOpenRouter多模型聚合平台
GOllama本地网络或本机上的 Ollama 服务
HLocal本机直接运行 GGUF 模型（llama.cpp）

除内置提供商外，你还可以添加任意 OpenAI-compatible 自定义端点，只需填写名称、Base URL 和 API Key。

第二章：首次使用四步

  1. 打开应用后，点击底部导航栏的 Settings（设置）。
  2. 进入 Settings → Provider，选择你要使用的提供商，点击添加 API Key。你可以为同一个提供商添加多个 Key，并分别命名别名。
  3. 进入 Settings → Models，点击 「Sync from All Providers」。橘子岛会从所有已配置有效 Key 的提供商拉取可用模型列表。
  4. 返回主界面，点击底部输入框，在模型选择器中选中一个模型，输入内容后发送即可开始对话。

第三章：模型选择与管理

同步完成后，所有可用模型会按提供商分类显示。你需要在 Settings → Models 中手动开启想用的模型，未启用的模型不会出现在聊天界面的模型选择器中。

模型 ID 格式为 ProviderName:model-id，例如 OpenAI:gpt-4o、Anthropic:claude-3-5-sonnet-20241022。

你可以为模型设置显示别名（Alias），方便在模型选择器中识别。部分提供商支持 Base URL 覆盖，用于代理或自托管场景。

对话支持 Per-message model switching，即在同一次对话的不同消息中使用不同模型。

第四章：聊天界面详解

橘子岛的聊天记录采用 树状结构（Tree-structured），而非线性列表。

  • 在任意模型回复上长按，选择 Regenerate，会生成一个同级分支回复，原回复不会被删除。
  • 在自己发送的消息上长按，选择 Edit，会基于修改后的内容生成新的分支。
  • 当一条消息存在多个分支回复时，消息旁会显示分支切换按钮，点击可在不同回复间切换。

输入框上方工具栏可开关：Thinking、Web Search、Code Execution、Shell、Image Gen、Transcription。

第五章：Thinking（推理模式）

开启 Thinking 后，模型会先输出内部推理过程，再输出正式回答。推理内容默认可折叠。

Thinking Level 分为 Low / Medium / High，可在 Settings → Generation 或对话级高级设置中调整。不是所有模型都支持 Thinking。

第六章：联网搜索

橘子岛支持 DuckDuckGo Lite（默认，无需 Key）、Brave Search、Serper、Tavily、SearXNG。模型可以调用 web_search 和 web_fetch 两个工具。

第七章：代码执行

代码执行基于本地 PRoot + Alpine Linux 沙盒。首次启用时会下载 rootfs。某些 VPN / tun 网络可能与 PRoot 冲突，导致代码执行失败，可尝试关闭 VPN 后重试。

第八章：远程 Shell（Conch 协议）

Conch 是橘子岛用于远程控制设备的私有协议。使用前，你必须先在自己的目标设备（服务器、电脑、NAS 等）上部署 Conch 服务端，然后在 Settings → Shell Devices 中添加设备。

Conch 协议采用 ECDH 密钥交换 + AES-256-GCM 加密 + HMAC-SHA256 签名，并具备 token bucket 速率限制与 nonce 防重放机制。

第九章：记忆（Memory）

橘子岛的记忆功能分为两类：

  • Active Memory（活跃记忆）：保存在 active_memory.md 中，会自动附加到每次对话的系统提示词末尾。
  • Saved Memory Files（记忆文件）：保存在 memory_db/*.md 中，模型可以通过工具自行创建、读取、编辑、删除。

第十章：RAG 对话搜索

RAG（Retrieval-Augmented Generation）允许模型搜索你历史对话的内容。使用 RAG 前需要配置嵌入模型。语义搜索基于余弦相似度计算，仅返回高于阈值的历史消息。

第十一章：本地模型（Local / Ollama）

橘子岛内置 llama.cpp，可直接在 Android 设备上运行 GGUF 模型。同一时间只能加载一个本地模型。Ollama 接入需要在局域网或本机上运行 Ollama 服务。

第十二章：系统提示词

系统提示词模板分为三段：System Prompt、User Prepend、User Append。支持变量替换，例如 {sent_time}、{sent_date}、{current_date}。

第十三章：图像生成

图像生成功能需要你自行配置 OpenAI-compatible 的图像生成接口。模型通过 generate_image 工具触发图像生成。

第十四章：数据导出、导入与备份

橘子岛支持导出 .橘子岛 文件，可包含：对话、记忆、系统提示词、设置、API Key。导入时支持 Merge（合并）、Replace（替换）、Skip（跳过）三种策略。还支持导入 Claude 和 ChatGPT 的导出文件。

第十五章：工作流（Workflows）

工作流有两种模式：Graph（节点图）和 Linear（线性）。支持的触发条件包括：手动、开机、定时、WiFi/蓝牙/电源/耳机连接断开、屏幕开关、应用启动/关闭、收到通知、地理围栏进入/离开等。Linear 工作流创建后需要用户审批才会真正启用。

第十六章：界面与主题

橘子岛采用 Material 3 设计，支持 Material You 动态取色。主题模式可在 Settings → Appearance 中切换：Light / Dark / System。

第十七章：语言与更新

橘子岛支持简体中文、繁体中文、英文。可在 Settings → Language 中切换。应用内置更新检查，可在 Settings → About 中手动检查。

第十八章：常见问题速查

  • 模型列表为空？ 检查 API Key、点击 Sync from All Providers、在 Models 页面启用模型。
  • 代码执行失败？ 检查 rootfs 是否已下载；若开启 VPN，尝试关闭后重试。
  • 本地模型加载慢？ 模型越大越慢，建议使用量化版本。
  • 搜索不到历史对话？ 检查 RAG、embedding 模型、缓存。

第十九章：隐私与安全风险须知

数据本地化但不等于绝对安全。橘子岛本身不收集你的数据，但你的聊天记录、API Key、记忆文件、系统提示词均存储在你的设备本地。设备丢失、Root 后被恶意应用访问、未加密备份泄露等风险由你自行承担。

消息会离开你的设备。你发送给模型的所有消息、附件、图片，都会传输到你配置的第三方 AI 提供商。这些提供商的隐私政策、数据留存、训练使用规则由各提供商决定，橘子岛无法管控。

API Key 安全由你负责。橘子岛使用 Android Keystore 加密存储 API Key，但如果你 Root 设备、截图分享设置页面、将导出文件上传到公开网盘、或在公共群聊中泄露 Key，责任由你自己承担。

导出文件包含敏感信息。.橘子岛 导出文件可能包含 API Key、聊天记录、记忆、提示词。请不要将该文件发送给陌生人、上传到不可信网盘、或保存在没有加密的共享存储中。

远程 Shell 具有真实系统权限。Conch 连接的是你自己的服务器，模型通过 Shell 工具执行的命令会真实作用于目标设备。请确保 Conch 部署在你拥有合法管理权限的设备上。

代码执行沙盒不是绝对隔离。PRoot + Alpine 沙盒提供有限的隔离，但不应被视为生产级安全沙盒。不要运行来源不明或高度可疑的代码。

联网搜索可能访问任意网页。Web Search 工具会抓取第三方网页内容，这些网页可能包含追踪脚本、恶意内容或不实信息。请自行判断搜索结果的可信度。

工作流自动化可能触发意外行为。请谨慎配置涉及 Shell、通知、网络请求的工作流，避免误操作或隐私泄露。
