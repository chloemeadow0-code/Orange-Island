## 第一章：橘子岛是什么

1.1 橘子岛是一款 **BYOK（Bring Your Own Key）Android AI 客户端**，它本身不提供 AI 聊天服务，而是作为统一入口，让你连接多个 AI 提供商。

1.2 使用橘子岛前，你必须自行准备至少一个 AI 服务提供商的 API Key。橘子岛不售卖、不提供、不赠送 API Key 或模型调用额度。

1.3 橘子岛支持以下 8 个内置提供商：

| 编号 | 提供商 | 说明 |
|---|---|---|
| A | OpenAI | GPT 系列、o1/o3 推理模型 |
| B | Anthropic | Claude 系列 |
| C | Google Gemini | Gemini 系列，支持代码执行与搜索插件 |
| D | DeepSeek | DeepSeek-V3 / R1 等 |
| E | Qwen（DashScope） | 阿里通义千问系列 |
| F | OpenRouter | 多模型聚合平台 |
| G | Ollama | 本地网络或本机上的 Ollama 服务 |
| H | Local | 本机直接运行 GGUF 模型（llama.cpp） |

1.4 除内置提供商外，你还可以添加任意 **OpenAI-compatible 自定义端点**，只需填写名称、Base URL 和 API Key。

## 第二章：首次使用四步

2.1 打开应用后，点击底部导航栏的 **Settings（设置）**。

2.2 进入 **Settings → Provider**，选择你要使用的提供商，点击添加 **API Key**。你可以为同一个提供商添加多个 Key，并分别命名别名。

2.3 进入 **Settings → Models**，点击 **「Sync from All Providers」**。橘子岛会从所有已配置有效 Key 的提供商拉取可用模型列表。

2.4 返回主界面，点击底部输入框，在模型选择器中选中一个模型，输入内容后发送即可开始对话。

---

## 第三章：模型选择与管理

3.1 同步完成后，所有可用模型会按提供商分类显示。你需要在 **Settings → Models** 中手动开启想用的模型，未启用的模型不会出现在聊天界面的模型选择器中。

3.2 模型 ID 格式为 `ProviderName:model-id`，例如 `OpenAI:gpt-4o`、`Anthropic:claude-3-5-sonnet-20241022`。

3.3 你可以为模型设置显示别名（Alias），方便在模型选择器中识别。

3.4 部分提供商支持 Base URL 覆盖，用于代理或自托管场景。设置路径：**Settings → Provider → 选择提供商 → Base URL**。

3.5 对话支持 **Per-message model switching**，即在同一次对话的不同消息中使用不同模型。长按输入框旁的模型按钮可调出模型选择器。

## 第四章：聊天界面详解

4.1 橘子岛的聊天记录采用 **树状结构（Tree-structured）**，而非线性列表。

4.2 在任意模型回复上长按，选择 **Regenerate**，会生成一个同级分支回复，原回复不会被删除。

4.3 在自己发送的消息上长按，选择 **Edit**，会基于修改后的内容生成新的分支。

4.4 当一条消息存在多个分支回复时，消息旁会显示分支切换按钮，点击可在不同回复间切换。

4.5 长按消息可执行：复制、编辑、删除、查看详情、切换分支等操作。

4.6 输入框上方工具栏可开关以下功能：

| 图标 | 功能 | 说明 |
|---|---|---|
| Thinking | 推理模式 | 启用后调用支持推理的模型（o1/o3/R1/Claude thinking/Gemini thinking） |
| Web Search | 联网搜索 | 模型可自动搜索网页 |
| Code Execution | 代码执行 | 在本地 Alpine Linux 沙盒中运行代码 |
| Shell | 远程 Shell | 调用已配置的 Conch 远程设备 |
| Image Gen | 图像生成 | 调用 BYOK 图像生成接口 |
| Transcription | 图片转文字 | 将图片 OCR 为文本供不支持视觉的模型使用 |

4.7 点击发送按钮右侧的齿轮图标，可打开 **Advanced Settings**，为当前对话单独设置温度、最大 token、top_p、频率惩罚、存在惩罚等参数，优先级高于全局设置。

## 第五章：Thinking（推理模式）

5.1 开启 Thinking 后，模型会先输出内部推理过程，再输出正式回答。推理内容默认可折叠。

5.2 Thinking Level 分为 Low / Medium / High，可在 **Settings → Generation** 或对话级高级设置中调整。

5.3 不是所有模型都支持 Thinking。橘子岛会根据所选模型自动判断是否显示 Thinking 开关。

5.4 推理过程也会计入 token 消耗，具体计费由你使用的 AI 提供商决定。

## 第六章：联网搜索

6.1 橘子岛支持以下搜索提供商：

- DuckDuckGo Lite（默认，无需 Key）
- Brave Search
- Serper
- Tavily
- SearXNG（可自托管）

6.2 设置路径：**Settings → Web Search**。你可以切换提供商、配置 Key、设置 Base URL、调整返回结果数量。

6.3 DuckDuckGo Lite 通过抓取 DuckDuckGo HTML 页面获取结果，属于 best-effort，可能在某些网络环境下不稳定。

6.4 模型可以在对话中主动调用 `web_search` 和 `web_fetch` 两个工具。

## 第七章：代码执行

7.1 代码执行基于本地 **PRoot + Alpine Linux 沙盒**。

7.2 首次启用时，应用会下载并解压 Alpine rootfs。rootfs 存储在应用私有目录中。

7.3 模型可以调用代码执行工具运行 Python、Shell 等命令，执行结果 inline 显示在对话中。

7.4 某些 VPN / tun 网络可能与 PRoot 的网络绑定冲突，导致代码执行失败。遇到此类问题可尝试关闭 VPN 后重试。

7.5 你可以在 **Settings → Sandbox** 中查看沙盒状态、安装 Alpine 软件包、重置 rootfs。

7.6 沙盒通过 Android Storage Access Framework（SAF）向外暴露文件系统，其他支持 SAF 的文件管理器可以访问沙盒中的文件。

---

## 第八章：远程 Shell（Conch 协议）

8.1 Conch 是橘子岛用于远程控制设备的私有协议，支持命令执行、文件读写、glob/grep 搜索。

8.2 使用 Conch 前，你必须先在自己的目标设备（服务器、电脑、NAS 等）上部署 Conch 服务端。

8.3 然后在 **Settings → Shell Devices** 中添加设备：填写名称、URL、API Key。

8.4 Conch 协议采用 ECDH 密钥交换 + AES-256-GCM 加密 + HMAC-SHA256 签名，并具备 token bucket 速率限制与 nonce 防重放机制。

8.5 一个橘子岛客户端可以配置多个 Conch 设备，模型会根据需要选择可用设备执行操作。

8.6 Conch 服务端代码通常部署在 `server/` 目录下，你需要具备一定的服务器运维能力。

---

## 第九章：记忆（Memory）

9.1 橘子岛的记忆功能分为两类：

- **Active Memory（活跃记忆）**：保存在 `active_memory.md` 中，会自动附加到每次对话的系统提示词末尾。
- **Saved Memory Files（记忆文件）**：保存在 `memory_db/*.md` 中，模型可以通过工具自行创建、读取、编辑、删除。

9.2 你可以在 **Settings → Memory** 中手动编辑 Active Memory 和管理 Saved Memory Files。

9.3 模型通过以下工具操作记忆：

- `list_memory_files`
- `read_memory_file`
- `create_memory_file`
- `edit_memory_file`
- `delete_memory_file`
- `update_active_memory`

9.4 记忆文件路径受防路径遍历保护，模型无法访问 `memory_db` 目录之外的文件。

---

## 第十章：RAG 对话搜索

10.1 RAG（Retrieval-Augmented Generation）允许模型搜索你历史对话的内容。

10.2 使用 RAG 前需要配置嵌入模型（Embedding Model）。你可以使用远程提供商的 embedding 接口，也可以使用本地 GGUF embedding 模型。

10.3 在 **Settings → Search** 中可以配置：

- 是否启用 RAG
- 搜索方法（语义搜索 / 关键词搜索 / 两者结合）
- 嵌入模型
- 相似度阈值（cosine similarity）
- 搜索结果数量上限
- 是否自动为新消息建立嵌入缓存

10.4 语义搜索基于余弦相似度计算，仅返回高于阈值的历史消息。

10.5 你可以在 **Settings → Search → Cache Management** 中手动重建或清空嵌入缓存。

---

## 第十一章：本地模型（Local / Ollama）

11.1 橘子岛内置 llama.cpp，可直接在 Android 设备上运行 GGUF 模型。

11.2 使用本地聊天模型的步骤：

1. 准备一个 GGUF 文件，放入设备存储。
2. 进入 **Settings → Provider → Local → Import GGUF Model**。
3. 设置上下文长度、温度、top_p 等参数。
4. 在聊天模型选择器中切换到该本地模型。

11.3 本地模型运行时依赖设备 NPU/GPU/CPU 性能，大模型可能导致发热、耗电、响应慢。

11.4 同一时间只能加载一个本地模型。切换本地模型时，前一个模型会被卸载。

11.5 Ollama 接入与 Local 不同：Ollama 需要在局域网或本机上运行 Ollama 服务，然后在橘子岛中添加 Ollama 提供商，Base URL 指向你的 Ollama 地址。

---

## 第十二章：系统提示词

12.1 系统提示词模板分为三段：

- **System Prompt**：系统角色设定
- **User Prepend**：自动附加在用户消息之前
- **User Append**：自动附加在用户消息之后

12.2 支持变量替换，例如：

- `{sent_time}`：消息发送时间
- `{sent_date}`：消息发送日期
- `{current_date}`：当前日期

12.3 你可以在 **Settings → Prompts** 中创建、编辑、删除、切换系统提示词。

12.4 每个对话可以单独设置系统提示词，也可以在全局设置中指定默认模板。

---

## 第十三章：图像生成

13.1 图像生成功能需要你自行配置 OpenAI-compatible 的图像生成接口。

13.2 设置路径：**Settings → Image Generation**。需要填写 Base URL、API Key、默认图像尺寸。

13.3 模型通过 `generate_image` 工具触发图像生成，生成结果 inline 显示在对话中。

13.4 图像生成按你配置的第三方服务商计费，橘子岛不收取任何费用。

## 第十四章：数据导出、导入与备份

14.1 橘子岛支持导出 `.橘子岛` 文件，可包含：对话、记忆、系统提示词、设置、API Key。

14.2 导出路径：**Settings → Data Control → Export**。导出时可选择类别。

14.3 导入 `.橘子岛` 时支持三种策略：

- **Merge（合并）**：与现有数据合并
- **Replace（替换）**：清空现有数据后导入
- **Skip（跳过）**：遇到冲突时跳过

14.4 橘子岛还支持导入 Claude 和 ChatGPT 的导出文件（.zip / .json）。

14.5 自动备份功能可在 **Settings → Data Control → Auto Backup** 中配置，支持设置备份周期、保留份数、备份类别。

## 第十五章：工作流（Workflows）

15.1 工作流允许你创建自动化任务，由特定事件触发，在满足条件后执行一系列动作。

15.2 工作流有两种模式：

- **Graph（节点图）**：手动搭建节点与连线，适合复杂逻辑。
- **Linear（线性）**：触发器 + 条件 + 动作，由 AI 辅助生成，更容易创建。

15.3 支持的触发条件包括：

- 手动触发
- 设备开机完成
- 定时（Time / Cron）
- WiFi 连接 / 断开
- 蓝牙连接 / 断开
- 电源连接 / 断开
- 耳机连接 / 断开
- 屏幕开启 / 关闭
- 应用启动 / 关闭 / 前台停留时长
- 收到通知
- 地理围栏进入 / 离开

15.4 创建 Linear 工作流后，需要用户审批才会真正启用。

15.5 工作流执行记录可在对应工作流详情中查看。

## 第十八章：常见问题速查

18.1 **为什么模型列表为空？**  
请先确认已添加有效 API Key，并已点击 **Sync from All Providers**，且已在 Models 页面启用对应模型。

18.2 **为什么代码执行失败？**  
检查是否已下载 rootfs；若开启 VPN，尝试关闭后重试。

18.3 **为什么本地模型加载很慢？**  
GGUF 模型首次加载需要从存储读取到内存，模型越大越慢。建议使用量化版本。

18.4 **为什么搜索不到历史对话？**  
检查是否已启用 RAG、是否已配置 embedding 模型、是否已为历史消息建立缓存。

## 第十九章：隐私与安全风险须知

19.1 **数据本地化但不等于绝对安全**。橘子岛本身不收集你的数据，但你的聊天记录、API Key、记忆文件、系统提示词均存储在你的设备本地。设备丢失、Root 后被恶意应用访问、未加密备份泄露等风险由你自行承担。

19.2 **消息会离开你的设备**。你发送给模型的所有消息、附件、图片，都会传输到你配置的第三方 AI 提供商（如 OpenAI、Google、Anthropic 等）。这些提供商的隐私政策、数据留存、训练使用规则由各提供商决定，橘子岛无法管控。

19.3 **API Key 安全由你负责**。橘子岛使用 Android Keystore 加密存储 API Key，但如果你 Root 设备、截图分享设置页面、将导出文件上传到公开网盘、或在公共群聊中泄露 Key，责任由你自己承担。

19.4 **导出文件包含敏感信息**。`.橘子岛` 导出文件可能包含 API Key、聊天记录、记忆、提示词。请不要将该文件发送给陌生人、上传到不可信网盘、或保存在没有加密的共享存储中。

19.5 **远程 Shell 具有真实系统权限**。Conch 连接的是你自己的服务器，模型通过 Shell 工具执行的命令会真实作用于目标设备。请确保 Conch 部署在你拥有合法管理权限的设备上，并为 API Key 设置足够强度。

19.6 **代码执行沙盒不是绝对隔离**。PRoot + Alpine 沙盒提供有限的隔离，但不应被视为生产级安全沙盒。不要运行来源不明或高度可疑的代码，不要在沙盒中处理涉及真实财产、生产凭证的敏感操作。

19.7 **联网搜索可能访问任意网页**。Web Search 工具会抓取第三方网页内容，这些网页可能包含追踪脚本、恶意内容或不实信息。请自行判断搜索结果的可信度。

19.8 **图像生成服务由第三方提供**。图像生成接口需要你自行配置，生成内容、内容审核、数据留存均由对应服务商负责。

19.9 **崩溃日志可能包含设备信息**。橘子岛可收集崩溃日志以改进产品，崩溃日志中可能包含设备型号、Android 版本、异常堆栈等信息。你可以在设置中关闭或选择不上传。

19.10 **工作流自动化可能触发意外行为**。工作流可在后台响应系统事件（如收到通知、进入地理围栏）并执行动作。请谨慎配置涉及 Shell、通知、网络请求的工作流，避免误操作或隐私泄露。

# QQ 问卷配置说明

## 一、平台选择

建议使用 **腾讯问卷（docs.qq.com/form）** 或 **问卷星**，然后分享到 QQ 群。QQ 问卷本身没有独立的“防截屏”能力，但可以做到：

- 一个 QQ 号/微信账号只能提交一次
- 限定答题时间、随机抽题、设置必答题
- 答题页禁止右键/复制（有限，不能阻止截屏）

## 二、一个号只能做一次设置方法

**腾讯问卷：**

1. 创建问卷 → 点击右上角「设置」
2. 找到「填写设置」→ 开启「每个用户/IP/设备只能填写一次」
3. 选择登录方式：QQ 登录 / 微信登录
4. 这样系统会记录登录态，同一个 QQ 号无法重复提交

**问卷星：**

1. 编辑问卷 →「设置」→「回收设置」
2. 开启「每个用户只能回答一次」
3. 选择身份验证方式：QQ / 微信 / 手机号

> 注意：如果关闭登录验证，仅通过浏览器 Cookie 限制，容易被清缓存绕过。建议强制 QQ 登录。

## 三、「没提交前不能截屏」的技术说明

**网页问卷（包括腾讯问卷、问卷星）做不到真正的防截屏。** 截屏是操作系统/硬件层行为，浏览器网页无法阻止。

**真正实现防截屏，必须在 Android 应用层做：**

在答题 Activity 的 `onCreate` 中设置 `FLAG_SECURE`：

```kotlin
window.setFlags(
    WindowManager.LayoutParams.FLAG_SECURE,
    WindowManager.LayoutParams.FLAG_SECURE
)
```

效果：
- 系统截图/录屏时黑屏
- 禁止最近的任务缩略图被读取
- 不能通过 adb 截图

**建议方案：**

如果你要在 QQ 群里做审核，有两个选择：

1. **在 App 内嵌入审核问卷页面**（WebView 加载腾讯问卷），同时给 WebView 所在 Activity 加 `FLAG_SECURE`。这样用户在 App 内答题时无法截屏。
2. **接受现实**：QQ 问卷网页版无法防截屏，只能靠「一个号只能做一次」+ 人工复核 + 答案随机化来降低作弊。

## 四、降低作弊的其他建议

- **随机抽题**：从 25 题中随机抽取 15 题，顺序打乱
- **限时答题**：设置 15-20 分钟，超过自动提交
- **答案不公开**：不要把答案键放到公共群
- **人工复核**：对全对但申请理由敷衍的，随机抽查
