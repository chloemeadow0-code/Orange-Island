# 橘子岛 · 工作流（Workflow）编写指南

> 工作流 = 一张**有向图**：节点做事，边决定走哪条路。引擎按拓扑顺序执行，每个节点的输出可以流给下游节点用。
>
> 本指南聚焦你关心的四件事：**主动发消息、查前台 app / 使用情况、跳转 app、复合图谱（条件分支 + 数据流）**。

---

## 0. 先记住三件事（避免 90% 的坑）

1. **数据在节点间靠「引用」流动**。一个节点的参数可以写成 `{{另一个节点的id}}`（引用），引擎执行时自动替换成那个节点的输出文本。这是整个图谱数据流的唯一机制。
2. **节点要执行，至少要有一条入边被满足**。没有入边（孤立）的节点会无条件执行；有入边但条件全不满足 → 被 `Skip`（日志里就是 `Incoming edge conditions not met`）。
3. **LLM 节点的输出是不稳定的自然语言**。要让下游稳定解析，prompt 里要**强制要求 JSON 输出**，并且 transform 的 jsonpath 提取已经做了清洗（能剥 markdown 围栏、抠 `{...}`），但 prompt 本身约束好更稳。

---

## 1. 节点类型（你能用到的全部）

| 节点 | 作用 | 关键字段 |
|------|------|----------|
| **start** | 入口，带触发器（定时/开机/手动/Intent）。一个图可以有多个 start | `trigger` |
| **action** | 调一个工具（`open_app`、`get_app_usage`…） | `toolName`、`args` |
| **llm** | 调大模型生成文本 | `prompt`、`provider`、`modelId`、`systemPrompt` |
| **branch** | 比较两个值，输出 true/false | `lhs`、`cmp`、`rhs` |
| **transform** | 加工字符串（正则/jsonpath/切片/拼接/随机/固定值） | `op` |
| **merge** | 把多个 true/false 归约成一个（AND / OR） | `reducer` |
| **notify** | 发系统通知 | `title`、`content`、`priority` |
| **chat_message** | 往聊天会话里发一条消息（主动消息！） | `text`、`participant`（MODEL/USER） |

---

## 2. 边（Edge）与条件（Guard）

边连接 `from → to`，可选一个 `guard` 决定这条边何时「点火」：

| guard | 何时点火 |
|-------|---------|
| `null`（无条件） | 上游节点正常完成（Done）时 |
| `on_success` | 上游成功时 |
| `on_failure` | 上游报错时（用来做错误分支） |
| `bool(true/false)` | 上游输出解析为布尔，且等于期望值。**用在 branch / merge 之后做分流** |
| `regex(正则)` | 上游输出包含正则匹配时 |

> 一个节点有多个入边时，**任意一条**满足就执行（OR 语义）。要 AND，用 merge 节点。

## 3. 四大场景实操

### 场景 A：主动发消息（聊天 / 通知）

**目标**：到点让 Silas 主动跟你说一句话。

```
[start: 每15分钟] ──> [action: get_foreground_app] ──> [llm: Silas思考] ──> [chat_message: 发聊天]
```

- **llm 节点**：prompt 引用 `get_foreground_app` 的输出，让模型根据「用户现在在用什么 app」生成一句关心的话。
  - `provider`/`modelId` 填你的（如 `亲亲老公:Silas`），或在工作流设置里绑定 modelId（`provider:modelId` 格式）覆盖。
- **chat_message 节点**：`text` 字段引用 llm 节点输出（`{{llm节点id}}`），`participant = MODEL`。
  - 这条消息会落到工作流绑定的 project 的会话里。
- **notify 节点**（可选替代）：要系统通知弹窗就用 notify，`title`/`content` 同样可引用上游输出。

> 这就是你「查岗小助手」的核心链路，现在已经能跑通了。

---

### 场景 B：查前台 app / 使用情况

两个**action 节点**直接调工具：

| 工具 | 入参 | 返回（JSON） |
|------|------|-------------|
| `get_foreground_app` | 无 | `{"foreground_app":"微信","package":"com.tencent.mm","foreground_seconds":120,"since":"..."}` |
| `get_app_usage` | `range`（`today`/`week`，默认 today）、`limit`（默认10） | `{"range":"today","apps":[{"app":"微信","package":"...","foreground_minutes":180,"last_used":"..."}],"count":3}` |

**前提权限**：
- 系统设置 → 使用情况访问（PACKAGE_USAGE_STATS）必须开。没开会返回 `permission_denied`。
- 设备访问页 → 「自动审批敏感读取」建议开着（默认开），否则后台工作流会被审批闸门挡（返回 `approval_denied`）。

**典型用法**：action 调完 → llm 节点引用它的输出 → 生成分析/关心语 → 发消息。

---

### 场景 C：跳转 app（打开某个应用）

**工具**：`open_app`，入参 `package_name`（如 `com.tencent.mm` 是微信）。

```
[llm 决定跳哪个] ──> [transform: 提取package] ──> [action: open_app]
```

- llm 让模型输出 `{"package":"com.tencent.mm","reason":"..."}`（**强制 JSON**）。
- transform(jsonpath) 节点：`path = package`，从 llm 输出里抠出包名。
- action(open_app)：`package_name` 引用 transform 的输出。

**前提权限（后台跳转才需要）**：
- 设备访问页 → 「显示在其他应用上层」（SYSTEM_ALERT_WINDOW）必须开。
  - 没开 + 后台触发 → 返回 `background_activity_blocked`，不会跳。
  - 前台手动跑工作流不需要这个权限（前台豁免）。

> 你日志里「跳转app 被 skip」是因为**入边条件没满足**——多半是前面某个 branch 判断没通过（比如 llm 输出的是自然语言没带跳转信号）。要么让 llm 稳定输出带跳转标志的 JSON，要么把入边改成无条件。

---

### 场景 D：复合图谱（条件分支 + 数据流）⭐

这是你最想掌握的——**根据条件走不同路**。核心是 **branch + bool 边**。

#### 范式 1：如果…就…（二选一）

```
[start] → [action: get_foreground_app] → [llm: 判断要不要提醒]
                                              │
                                    (输出 true/false)
                                              ↓
                                        [branch: == "true"]
                                         ↙            ↘
                              bool(true)              bool(false)
                                  ↓                      ↓
                         [chat_message: 提醒]      （不执行，链路结束）
```

**关键点**：
- **llm 节点** prompt 里要求只输出 `true` 或 `false`（例如：「如果用户在社交app超过1小时，只回复 true，否则只回复 false，不要任何其他文字」）。
- **branch 节点**：`lhs = {{llm节点id}}`，`cmp = EQ`，`rhs = "true"`。输出 true/false。
- 两条出边：一条 `bool(true)` → 提醒，一条 `bool(false)` → 不做事（或走别的分支）。

#### 范式 2：提取 LLM 输出的结构化字段

llm 输出 JSON，用 **transform(jsonpath)** 拆字段：

```
[llm: 输出 {"action":"notify","msg":"喝水去","app":"com.tencent.mm"}]
   ├──> [transform jsonpath: msg]    ──> [chat_message: {{msg}}]
   ├──> [transform jsonpath: app]    ──> [action: open_app {{app}}]
   └──> [transform jsonpath: action] ──> [branch: == "notify"] ──bool(true)──> ...
```

- **transform 节点的输入**默认取它**第一条入边**的上游输出（就是 llm 的输出）。
- jsonpath 的 `path` 用点号路径，如 `msg`、`data.items[0].name`。
- 已内置清洗：llm 输出即使带 ` ```json ` 围栏或前置废话也能抠出 JSON。但**prompt 里要求纯 JSON 仍是最稳的做法**。

#### 范式 3：多条件合并（AND / OR）

要「条件1 **且** 条件2」都满足才执行：

```
[branch1] ──┐
            ├──> [merge: ALL_TRUE] ──bool(true)──> [执行节点]
[branch2] ──┘
```

- merge 节点 `reducer = ALL_TRUE`（AND）或 `ANY_TRUE`（OR）。
- merge 的入边来自各个 branch，出边用 `bool(true/false)`。

#### 范式 4：错误处理（try/catch）

工具调用可能失败（权限没给、网络错）。用 `on_failure` 边兜底：

```
[action: open_app] ──on_success──> [chat_message: 已跳转]
                   └──on_failure──> [notify: 跳转失败，检查权限]
```

## 4. 触发器（什么时候跑）

start 节点的 `trigger`：

| 触发器 | 配置 | 场景 |
|--------|------|------|
| **Schedule / Interval** | `{intervalMs: 900000}`（15分钟） | 定时查岗、定时提醒 |
| **Schedule / OneShot** | `{atMs: 时间戳}` | 一次性闹钟式触发 |
| **Schedule / CronLike** | `{expr: "cron表达式"}` | 复杂时间规则 |
| **AppOpen** | 无 | 橘子岛冷启动时跑一次 |
| **IntentAction** | `{action: "..."}` | 外部 app 广播 Intent 触发 |
| **Manual** | 无 | 只能手动「立即运行」 |

> 后台触发（Schedule/Interval）的工作流，工具调用走的是后台白名单 + 审批自动放行 + 悬浮窗权限（跳转用）。前台手动跑则全放行。

## 5. 常见坑速查

| 现象 | 原因 | 解决 |
|------|------|------|
| `Skipping '节点': Incoming edge conditions not met` | 入边 guard 没满足 | 检查上游 branch/llm 输出是否如预期；或把边改无条件 |
| `approval_denied` | 敏感读取没自动审批 | 设备访问页开「自动审批敏感读取」 |
| `permission_denied`（usage） | 没开使用情况访问 | 系统设置 → 使用情况访问 |
| `background_activity_blocked`（open_app） | 后台跳转没悬浮窗权限 | 设备访问页开「显示在其他应用上层」 |
| `Provider 'xxx' is not registered` | provider 没注册好 | 检查 provider/modelId 配置；现已不会偷偷回退到 Gemini |
| LLM 404（Gemini 路径） | 历史竞态，已修复 | 确保 provider 注册完成才调用 |
| transform 提取失败/空 | LLM 输出非 JSON | prompt 强制 JSON 输出；已内置清洗兜底 |
| branch 误判（空==空） | 上游提取失败返回空 | 同上，修好提取；或给 fallback 设非空默认值 |

## 6. 一个完整的「查岗 + 智能跳转」复合图谱示例

```
[start: 每15分钟]
    │
    ├─> [action: get_foreground_app]  ──┐
    ├─> [action: get_app_usage]        ──┤
    │                                     ↓
    └───────────────────────────> [llm: Silas思考]
        prompt: 引用上面两个action的输出，要求输出JSON：
                {"should_remind": true/false, "message": "关心的话", "jump_app": "包名或空"}
                                      │
                 ┌────────────────────┼────────────────────┐
                 ↓                    ↓                    ↓
    [transform: jsonpath should_remind]  [transform: jsonpath message]  [transform: jsonpath jump_app]
                 │                    │                    │
        [branch: == "true"]      [chat_message: {{message}}]   [branch: != ""]  (jump_app 非空)
           ↙ bool(true)                                    ↙ bool(true)
    （可继续分支）                              [action: open_app {{jump_app}}]
```

**要点**：
- 两个 action 并行调（都从 start 出边），llm 同时引用两者输出。
- llm **强制 JSON 输出**，三个 transform 分别抠字段。
- message 无条件发（聊天）；jump_app 只有非空时才跳（branch 判断）。
- 跳转节点入边用 `bool(true)`，jump_app 为空时自然被 skip——**这是你想要的条件跳转**。
